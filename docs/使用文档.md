## 一、启动与环境

```bash
npm install          # 首次
npm run dev          # 启动应用（开发模式）
```

默认监听端口：

| 端口 | 用途 |
|---|---|
| 9090 | HTTP 代理入站（含 CONNECT 隧道） |
| 9091 | SOCKS5 入站（手机 / 自定义客户端） |
| 9092 | 内置 MCP 服务器（默认关闭，见第十节） |

数据目录：`~/Library/Application Support/prism/data/`

- `data/data/proxy.db` — 流量库（flows / bodies / ws_messages 等表）
- `data/certs/` — CA 与叶子证书缓存
- 保留策略默认：30 天 / 20 万条 / 磁盘 10GB（设置页可调）

顶栏 **Proxying** 徽标表示代理在监听；红点为录制开关（无痕），⚡ 为极速模式。

## 二、首次配置：HTTPS 解密

**Mac 本机抓包：**

1. 系统代理指向 `127.0.0.1:9090`（设置页有指引），或工具直接配代理。
2. 设置页 →「证书信任」→ 信任内置 CA（`data/certs/ca.pem`，CN=Prism Root CA）。也可用钥匙串访问手动导入并设为始终信任。
3. 之后 HTTPS 流量即可解密查看（MITM）。

**SSL Pinning / 不想解密的域名**：设置页 `bypassHosts` 添加域名（支持通配），代理对这些目标直通不解密；`rejectUpstream` 控制上游证书校验行为。

**验证链路**：`curl -x http://127.0.0.1:9090 https://example.com -I` 应返回 200。

> 内置虚拟主机 `cert.local` 用于证书下载，不出现在流量列表——验证抓包请用外部 URL。

## 三、流量页

### 列表

- **虚拟滚动**，单机数万条不卡。
- **列自定义**：表头右键或拖动 —— 显隐 / 拖宽 / 持久化。
- **多 Tab 详情**：同时打开多条流量的详情对比查看。
- **多选**：Ctrl / Shift 点选，支持批量重放。
- **彩色高亮**：右键给行上色；标签（label）与备注（note）可写。

### 键盘导航

| 按键 | 作用 |
|---|---|
| `j` / `↓` | 下一条 |
| `k` / `↑` | 上一条 |
| `⌘F` / `Ctrl+F` | 聚焦过滤框 |
| `Esc` | 清空过滤 / 关闭弹层 |

### 详情面板

- **概览**：请求/响应头、状态、耗时，Timing 瀑布条（DNS / TCP / TLS / TTFB / 下载六段细分；HTTPS 无 TLS 段时显示「连接复用」徽标）；开启请求跟踪后显示 Trace ID。
- **请求/响应体**：自动解压 gzip/br/deflate；JSON 格式化；BodyViewer 按 Content-Type 渲染。
- **WebSocket**：时间线逐帧查看。
- **gRPC**：Protobuf 解码 + trailers。
- **⚡ 手动插件解码**：对历史流量跑解码插件，不覆盖原始数据。

### 右键菜单

复制 URL / 复制 cURL / Composer 打开 / 加入 Collection / 重放（可 N 次 + 间隔）/ 任意两条 diff / 标签备注 / 按 Trace ID 过滤。

### 工作台侧栏

我的收藏 / 书签（文件夹树 + 拖拽）、设备（双击改名）、应用分组、域名分组。点击行即按对应条件过滤。

## 四、过滤语法

过滤框支持 `key:value` 组合与纯文本（多条件 AND；值用双引号包住可含空格）：

| Key | 说明 |
|---|---|
| `host:` | 域名包含 |
| `path:` | 路径包含 |
| `url:` | 完整 URL 包含 |
| `method:` | 精确匹配，`\|` 分隔多选（`method:get\|post`） |
| `status:` | 状态码；支持 `2xx` 通配与多选（`status:404\|500`） |
| `app:` | 客户端应用名（手机流量按应用过滤） |
| `ip:` | 客户端 IP |
| `label:` / `note:` | 标签 / 备注包含 |
| `trace:` | Trace ID（前缀即可） |
| `sni:` | TLS SNI 域名包含（MITM 流量的握手域名） |
| `body:` | 请求/响应体内容包含（MCP / 书签过滤生效；UI 列表为内存过滤不含 body，不生效） |
| `type:` | `http` / `tunnel` / `grpc`… |
| `flag:` | 特性标记（如 `flag:grpc`） |
| `has:` | `response` / `reqbody` / `respbody` / `error` |
| 纯文本 | 在 host+path+url 中模糊匹配 |

示例：`host:api.example.com status:2xx app:微信`

## 五、调试能力

### 断点

断点页创建规则（URL 条件），命中后流量**暂停**在代理内，弹窗编辑请求/响应后放行——改参数、改返回值、模拟异常。

### 规则引擎

规则页按顺序匹配，实时预览命中。动作类型：

| 类型 | 作用 |
|---|---|
| mock | 直接返回指定内容（状态/头/体） |
| map-local | 返回本地文件内容 |
| rewrite-request / rewrite-response | 搜索替换（正则）改写头/体 |
| block | 拦断 |
| hold | 挂起（不响应） |
| throttle | 限速 |
| bypass-tls | 该域名不解密 |

### 弱网与网络模拟

工具栏下拉一键切换五个预设：弱网（16kbps/800ms/丢包10%）/ 2G / 3G / 4G / 断网，可限定 host；需要任意参数的限速用规则引擎的 throttle 动作。

### 重放与对比

- 任意请求重放（含修改后重发、N 次 + 间隔压测）。
- 两条流量 diff（FlowDiff 模态）：请求/响应头体逐行对比。

### 其他引擎能力（设置页配置）

- **上游代理（二级代理）**：出站流量转发给上游 HTTP/SOCKS5。
- **反向代理**：本地端口透明转发到远程地址，规则/断点/插件照常生效。
- **域名镜像**：源域名流量改道镜像域（SNI 同步替换，支持 `*.example.com` 通配）。
- **访问控制**：客户端 IP 白/黑名单，TCP 层直接断开（`::ffff:` IPv6 映射自动归一化）。
- **请求跟踪**：工具栏 ⌖ 开启后每个上游请求注入 `X-Trace-Id`（头名可配），配合 `trace:` 过滤串联一次操作的全部请求。
- **无痕模式**：红点暂停 = 引擎级不落库、不推送、不写消息表。
- **极速模式**：⚡ 流量仅内存实时展示不写盘（压测场景，重启清空）。

## 六、Composer（API 测试）

多 Tab 请求编辑器（脏标记琥珀点，草稿跨重启持久化）。五个编辑区：

1. **参数**：Query KV 表格 ⇄ 文本模式（`#` 停用行）。
2. **请求头**：同样支持表格 ⇄ 文本。
3. **请求体**：8 种格式（JSON / 表单 / XML / 二进制等），JSON 美化/压缩；从流量打开时按 Content-Type 智能回填。
4. **授权**：Bearer / Basic / 自定义头（从流量回填自动识别）。
5. **前置脚本**：JS——签名、注入头、改 body；错误独立提示不影响发送。

其余能力：

- **自定义 method**：输入框直接键入任意方法（datalist 提示常用值）。
- **环境变量**：`{{var}}` 占位，多套环境切换。
- **Cookie 管理**：按域注入。
- **请求历史**：最近 50 条，一键回填。
- **操作菜单 8 项**：下载响应 / 重置 / 清除 / 导入报文 / 导入 cURL / 导出 cURL / 生成代码（cURL / Python / fetch / axios / Go）/ 管理 Cookie。

## 七、工具箱

## 八、手机接入（Android）

APK 构建：`cd android && ./gradlew assembleDebug`（需 JDK 21 + Android SDK；产物在 `app/build/outputs/apk/debug/`）。要求设备已 Root。

### 方案一：Wi-Fi（同局域网）

1. Mac 与手机连同一 Wi-Fi。
2. Mac 设置页 →「手机接入指引」→ 出示配对二维码。
3. 手机 App → 扫码配对（自动填入 Mac IP）→ 打开 VPN 隧道开关。

### 方案二：USB（无 Wi-Fi，更稳）

1. USB 连接，Mac 设置页 →「USB 数据线」Tab → **一键建立**（自动 `adb reverse` 9090/9091 两通道，每 4s 轮询通道状态）。
2. 手机 App → 方案切「USB 数据线」→ 地址自动回填 `127.0.0.1` → 打开 VPN 隧道开关。

### 分应用代理

App 内「分应用代理」选择模式（全部 / 仅选中 / 排除选中）。

### CA 证书（HTTPS 解密，需 Root）

手机 App →「CA 证书安装」→「一键安装」：

- 经 SOCKS5 从 Mac 下载 CA（地址取当前方案槽位），base64 内嵌注入。
- Android 14+：bind-mount 到 `/apex/com.android.conscrypt/cacerts` 并 nsenter 注入所有运行中进程；重启后 BootReceiver + App 冷启动双通道自动重放（挂载已在位时秒级跳过，全量重放约 1~2 分钟）。
- Android <14：直接写 `/system/etc/security/cacerts`，持久生效。

> **重要**：装完后**已运行的 App 不会读新证书库**（Conscrypt 进程启动时缓存证书列表）——需强停重开目标 App，或直接重启手机。安装成功后新启动的 App 全部信任。

**Root 提权**：默认 `su`（Magisk/KernelSU 等标准方式）；改版内核后门设备长按 Root 状态行填写对应提权魔数命令（App 持久化保存，重启不丢）。

**应用归属**：手机流量经 SOCKS5 RFC1929 用户名上报应用名，流量列表「App」列即显示来源应用（如「微信」「浏览器」）。VPN 冷启动第一条或 curl 直连 127.0.0.1 的流量可能显示 `adb`（Mac 侧 lsof 归属降级），属预期。

## 九、Headless CLI 模式

无 Electron 依赖的代理核心，适合服务器 / CI / 远程抓包。流量摘要输出 stdout，日志 stderr。

```bash
npm run cli -- [选项]

  --data-dir <dir>    数据目录（证书 / SQLite / 插件），默认 $PRISM_DATA_DIR 或 ~/.prism
  --port <n>          HTTP 代理端口（默认读已保存设置，初始 9090）
  --socks-port <n>    SOCKS5 端口，0 = 禁用（默认 9091）
  --bind <addr>       监听地址（默认 0.0.0.0）
  --quiet             只输出流量摘要
```

示例：

```bash
npm run cli -- --port 9090
npm run cli -- --data-dir ./capture-session
PRISM_DATA_DIR=/tmp/cap npm run cli
```

## 十、MCP 服务器（AI 集成）

让 Qoder / Claude 等 AI 客户端直接查询抓包数据，联合调试。

1. 设置页 →「MCP 服务器」→ 开启（默认端口 9092，仅监听 127.0.0.1）。
2. AI 客户端配置端点：`http://127.0.0.1:9092/mcp`（Streamable HTTP，无状态）。

提供三个工具：

| 工具 | 作用 |
|---|---|
| `list_flows` | 列流量，支持上述过滤语法 + limit（上限 500） |
| `get_flow` | 按 id 或 seq 取完整 Flow JSON |
| `get_flow_body` | 取请求/响应体，自动解压 gzip/deflate/br，超 2 万字符截断 |

验证：`curl -s http://127.0.0.1:9092/mcp -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'`

## 十三、常见问题

**Q：手机发烫卡死怎么办？**
两类原因：① **CA 系统证书挂载脚本堆叠事故（旧版本 bug，已定位待修复）**——早期版本的挂载脚本对每个进程重复执行 nsenter 挂载，在共享挂载命名空间的设备上层层堆叠出上万个 bind 挂载点，拖慢全系统进程启动直至 watchdog 卡死；表现为装包/启动 App 后几分钟内整机冻结，只能长按电源 + 音量上强制重启。修复版本（按唯一挂载命名空间去重）发布前的临时处理：在电脑上执行 `adb shell pm disable-user --user 0 com.prism.debug` 停用本应用可彻底避免复发；② VPN 开着但 Mac 代理不可达（Mac 睡眠/重启/退出）——全机流量黑洞、各 App 疯狂重试导致发热。②已内置防护：代理持续不可达约 1 分钟后 VPN 自动断开恢复直连（App 状态行有红字提示，真机已验证），重连 Mac 后在 App 里重新打开隧道即可。

**Q：手机装完 CA 后浏览器仍报证书错误？**
运行中的 App 缓存了旧证书列表。强停该 App 重开，或重启手机。

**Q：真机上用 curl 验证 HTTPS 一直 exit 60？**
系统 curl（BoringSSL）的 CApath 是老路径 `/system/etc/security/cacerts`，不读 apex bind-mount。用 `--cacert` 显式指定 CA（PEM 格式；给 DER 会 exit 77）。Java/Conscrypt 层才读 apex——验证「全部 App 生效」请用浏览器等真 App。

**Q：MITM 某域名失败 / 客户端报证书锁定？**
App 做了 SSL Pinning。设置页 `bypassHosts` 加该域名直通不解密。

**Q：手机流量 App 列显示 `adb`？**
USB 方案冷启动第一条或 curl 直连场景的 lsof 降级归属，属预期；Wi-Fi 方案与正常 VPN 隧道流量均按应用名归属。

**Q：adb reverse 通道失效？**
拔线后通道即断，Mac 设置页轮询状态会实时反映；重插后点「一键建立」即可。

**Q：端口被占 / 换端口？**
设置页改代理端口或 MCP 端口，实时生效；端口占用时仅 warn 不崩。

## 十四、开发与验证命令

```bash
npm run typecheck        # 全包 TS 检查（node + web 两套 tsconfig）
npx vitest run           # 108 个测试（core 集成 + UI store）
npx electron-vite dev --remoteDebuggingPort 9222   # dev + CDP（E2E 用）
npm run cli              # headless 模式
cd android && ./gradlew assembleDebug              # Android APK
```

开发注意（详见 PROGRESS.md「开发必读」）：

- **IPC 三件套**：`packages/shared/src/ipc.ts` 契约 + `src/main/index.ts` handle + UI `call()`，缺一处 typecheck 红。
- 改 core / src/main / shared 后**必须重启 dev server**（渲染层 HMR 不覆盖主进程；重启会让手机 VPN 闪断几秒）。
- 新过滤 key 要同时改 `shared/search.ts` 的 `matchNode` 和 `core/db/flows-repo.ts` 的 `buildWhere`。
- `setSettings` 是浅合并——子对象（如 `capture`）要展开传全字段。
- 渲染层禁用 `Buffer`（组包用 TextEncoder/atob/btoa，有静态守卫测试）。
